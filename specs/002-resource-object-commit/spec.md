# Feature Specification: 完整资源版本、不可变对象与正式提交

**Feature**: `002-resource-object-commit` · M2
**Created**: 2026-10-20
**Status**: **approved / Q1–Q3不变；2026-10-21按用户明确决议分核心工程与延后发布验收，当前实施范围只见统一授权记录**
**当前授权**：[统一授权记录](<../001-host-workspace-foundation/authorization.md>)。规格批准是需求基线；002已批准核心范围的工程完成及发布缺项只见[tasks当前状态](<tasks.md#当前状态>)，001工程通过不替代002证据。本次文档维护未重跑业务验证。

**阅读导航**：§1用户结果 → §2范围/非目标 → §3故事 → 原FR/SC；[计划阅读入口](<plan.md#design-guide>)解释如何设计，[任务](<tasks.md>)沿Owner/依赖/US到验证与证据。**白话概念**：对象ready只证明附件字节就绪，不是资源已保存；正式版本/receipt由同一数据库提交确认；投影只是可再生清单，不是第二保存器。安装预算、区分配和运行名额是不同限制，逻辑满额验证不等于真实盘满或物理峰值证明。

## 1. 问题、用户与目标

001 已证明独立 Host、可信连接、工作区生命周期与最小文本的真实保存/完整停机重开；其正文直接入库，尚未交付对象协议或通用历史读取。依据是 [001 需求](<../001-host-workspace-foundation/spec.md#functional-requirements>)，不是从现有表或目录名推定新产品行为。

工作区使用者需要保存含附件的非执行型内容，准确读取任一已确认版本；客户端开发者需要知道字节何时可被正式引用、保存是否真的完成，以及断连/失败后如何调查原提交，而不是在文件、缓存与数据库之间猜测事实。

本片继承 [宪章](<../../.specify/memory/constitution.md>)，只细化 [唯一路线 M2](<../../docs/scope.md#9-唯一阶段路线与退出证据>) 与 [长期数据约束](<../../docs/scope.md#31-长期数据策略与单一实现范围designed未实现>)：

- 工作区数据库拥有正式资源、版本、引用、Head 与保存回执；不可变对象保存精确最终字节。候选、投影、安装登记都不是第二写入 owner。
- 对象可被接收/验证但尚未形成正式资源；只有用户确认且正式提交被证实成功，才能对外报告该版本已保存。
- 旧版内容及其对象不随新版改变；确认后的完整资源可在 Host 完整停止、全新进程重开后读取。
- 对象未就绪、陈旧候选、提交 unknown、已提交后投影失败分别有真实、可调查的结果，不以“全部失败/全部成功”掩盖。

## 2. 已批准的范围与评审边界

用户于 2026-10-20 明确确认第 9 节三项边界并批准本规格；下表是本片需求基线。技术设计仍须在 plan 冻结并实际验证，不能把批准等同实现。

| 方面 | 已批准范围 | 明确不承诺 |
| --- | --- | --- |
| 资源首片（Q1） | 延续非执行型文本记录，允许一版关联 0..N 个不透明字节附件；标题/正文/附件逻辑名称、长度、摘要与归属构成完整可读内容 | Agent/Workflow/页面/技能/知识的业务 schema、结构/依赖解析、执行、renderer；附件即使是代码也不运行 |
| 确认单元（Q2） | 一次确认保存**一个资源及其完整附件集合的一版**；每版不可变，区级 Head 定序 | 多资源/依赖集合的原子发布、整个工作区内容快照；A/B 跨库原子提交 |
| 历史 | 按稳定资源与明确版本读取完整内容/附件；有界列举该资源的已确认版本及其提交关联 | 回滚到旧版、删除/归档、裁剪历史、历史 GUI、版本合并 |
| 投影 | 至少一种明确标识版本/提交关联的已提交内容清单投影，可由正式事实显式再生成 | 通用外部目录导入、文件监听自动 Apply、Studio/Build；投影生成不构成第二次提交 |
| 001 兼容（Q3） | 同一 Host 继续支持原 001 工作区目录的原能力；M2 能力仅对显式新建的 M2 目录开放；旧工作区不升级 | 本片已有工作区升级器、数据搬迁、克隆、备份恢复；不得用“仍可另跑旧 binary”代替保留旧能力 |
| 容量校准（已确认） | 有限安装总保留预算＋每区分配；当前安装操作员可显式查看、预览并确认有限调额，满额拒新分配但保留调查/关闭/管理 | 不新增清理，不自动 GC；正式历史、有效候选、unknown 证据及实际占用不因重启/取消/TTL 消失；不承诺永不写满 |
| 窄安装演进（已确认） | 仅安装库持久预算所需的显式、有界 schema 演进，当前操作员确认、排他/排空、版本/校验及失败/unknown 恢复均须验收 | 不升级/搬迁任何 001 工作区，不做通用迁移框架、不在 open/inspect 隐式升级 |

**排除**：M3 通用外部候选/差异导入/Apply/Build/Studio，M4 插件，M5 Provider/Run/事件平台，M6 前端交付，M7 通用迁移/快照/备份/克隆/历史替换，M8 跨平台。无自动 GC、跨区对象共享/存在性查询、对象公开静态文件服务、远端访问、真实数据导入或任何未知副作用自动续跑。不创建空扩展目录/平台来冒充交付。

技术编号、对象键/摘要算法及字节编码、磁盘布局、具体路由与 DTO、传输分块、连接策略、发布/刷写机制留给后续 plan/research；不是本轮用户选择题。目录格式、安装/工作区 schema 与公共 API 必须分别演进，不把技术选择提前写成已实现事实。

## 3. 用户场景与独立验收

### US1 · 明确保存含对象的完整资源（P1）

作为工作区使用者，我要在确认前检查精确内容和附件，在确认后获得唯一正式版本，而不是把“上传完成”当保存。

**独立验收**：全新合成工作区，通过普通公开客户端接收对象、预览、确认、读取；比较正式状态与精确字节。

1. **Given** 两个内容不同的合成附件已接收并验证，**When** 用户只预览而不确认，**Then** 没有新正式版本/Head/成功回执；预览列出该版将包含的全部内容、对象和基线。
2. **Given** 该预览仍有效且授权当前有效，**When** 用户确认，**Then** 正式引用前最终字节已存在且摘要验证；正式版本、当前指针、Head、回执和关联作为一个正式提交结果被读取。
3. **Given** 对象缺失、未完成、摘要不符或提交前被替换，**When** 预览/确认达到相应校验门，**Then** 拒绝其正式引用，不改变已有正式内容，不返回保存成功；单有客户端摘要不构成证据。
4. **Given** 用户改变附件字节、名称/集合、正文或目标，**When** 尝试沿用旧确认，**Then** 拒绝；必须重新预览并显式确认，不把旧批准扩大到新内容。

### US2 · 完整历史与全进程重开（P1）

作为使用者，我要读取每一已确认版本，而非只看到历史编号或随最新指针变化的附件。

**独立验收**：保存 v1（两个附件），再保存 v2（替换一个、移除另一个）；关闭全部工作区、正常结束 Host，以全新进程与新认证重开，逐字节比较两版。

1. **Given** v1 已确认，**When** v2 确认，**Then** v1 的内容、附件集合/字节、版本关联不变；当前读取精确返回 v2；全区 Head 不是多资源快照声明。
2. **Given** Host 与客户端缓存均不再存在，**When** 新进程重新取得当前授权及真实排他后读取明确版本，**Then** 稳定身份、正文、附件原始字节、摘要、原提交关联一致。
3. **Given** 查询未确认/不存在的版本，或带 A 的版本/对象关联向 B 查询，**Then** 受限拒绝，无目标内容/对象存在性泄露；历史 ID、哈希、旧 URL 不授予访问权。
4. **Given** 多于一页历史，**When** 有界分页读取，**Then** 页边界/顺序可确定且不能换目标/主体，不能只返回 metadata 冒充完整内容能力。

### US3 · 陈旧、并发、重复及未知结果（P1）

作为客户端开发者，我要在并发及断连后调查原提交，而不是重发或自动覆盖。

**独立验收**：两个真实客户端在同一基线预览不同字节/附件；制造提交阶段失败和丢回执，按原工作区与原 operationId 查询/显式调查。

1. **Given** 两个候选同旧基线，**When** 并发确认，**Then** 最多一个正式成功；另一方明确冲突，零自动合并/覆盖。
2. **Given** 同区同 key、同主体、同精确输入已确认，**When** 后来候选过期、epoch/Head 改变后获授权调查，**Then** 仅返回原唯一结果，不再次发布对象或提交新版本。不同输入/主体复用 key 拒绝且不泄旧结果。
3. **Given** 对象就绪但正式事务确定拒绝，**Then** 旧正式状态保持；遗留对象不是新正式版本，不由扫描自动提升。
4. **Given** admission/正式提交不能证明结果，或确认后响应丢失，**When** 原 key 调查，**Then** 分清已确认、确定未提交、仍 unknown；缺回执/有对象/超时均不足以推断可重试，不自动换 key 或重放。
5. **Given** A/B 碰巧使用相同 key、对象字节、名称，**Then** 各自在本区授权与持久历史内关联，不建立全局业务去重/跨区 hash oracle。

### US4 · 投影失败不抹掉正式保存（P1）

作为使用者，我要在正式保存后清楚知道投影视图是否可用，并能恢复视图而不重复保存。

**独立验收**：真实投影生成写入失败/目的地冲突，对照数据库正式读取、唯一回执、未提交候选字节；解除条件后显式再生成。

1. **Given** 正式版本已经确认，**When** 投影生成失败，**Then** 原保存仍是同一个已确认结果；另报投影失败/过期及目标版本，不冒充回滚、unknown 或再次保存。
2. **Given** 待生成位置有未提交候选或不可信替换，**When** 生成/再生成投影，**Then** 拒绝覆盖候选/越界写；原字节不变。位置安全不由名称/PID/客户端路径声明证明。
3. **Given** 投影已缺失/陈旧且正式事实完整，**When** 有权限用户请求再生成，**Then** 从指定正式版本重建派生视图，不移动 Head、不新增正式版本/receipt，不修改候选。
4. **Given** 投影宣称一个版本但内容不符，**Then** 不把它当正式事实或拿它替代对象校验；普通正式读取不依赖投影成功。

### US5 · 对象 IO 的排空、隔离与当前权限（P1）

作为多工作区使用者，我要 A 对象慢 IO/失败/关闭不误关 B，且撤权后不能从旧对象引用继续取内容。

**独立验收**：A/B 各有正式资源；实际悬置对象发布/校验/投影物理 IO，执行断连、等待取消/超时和关闭；B 独立新增/更新/读取；另测权限及共享安全 unknown。

1. **Given** A 的字节操作尚未物理结束，**When** 等待者取消/超时/断连或用户关闭 A，**Then** 不从连接推断回滚/IO 已结束；关闭拒新准入，持有需要的实际资源/排他，不能宣称安全移动/已关闭。
2. **Given** A 局部对象损坏、失败或仍排空，**When** B 执行不依赖 A 的合法新增/更新/读取，**Then** B 正常完成；A 错误不被包装成全安装错误。共享认证/安装事实 unknown 则依赖操作如实阻断并解释作用域。
3. **Given** 原操作已接受且随后撤权，**When** 响应/历史/对象字节请求到达，**Then** 重查当前权限，不泄露目标内容；物理收尾不因撤权被假称完成，持久结果不被改写。
4. **Given** 上传、下载、候选与保存占用达到每区/安装上限，**When** 新请求进入，**Then** 有界拒绝/背压；调查/关闭保留可运行能力，不因每目录拆份放大全局预算；实际结束前不归还仍占用资源。

### US6 · 保留 001 与拒绝隐式升级（P1；Q3 已确认）

作为已有工作区使用者，我要更新 Host 后仍能使用原能力，而不是打开时被静默改库或丢失旧提交历史。

**独立验收**：用 001 支持的创建/文本保存路径得到非空合成目录，交给拟接替的 002 Host；同时验证全新 M2 目录。

1. **Given** 合法 001 目录及原记录/版本/receipt，**When** 002 Host 使用原文本能力预览、确认、关闭、完整停机重开，**Then** 原身份/正式历史保持，新文本保存仍有效；不要求两个 Host 并存来实现兼容。
2. **Given** 001 目录请求 M2 附件/新历史或投影能力，**Then** 按能力矩阵明确 unavailable，不在 open/inspect 时创建对象、补表、改 ledger、迁移或换身份；成功能力不可虚报。
3. **Given** 新建 M2 目录，**Then** 仍能完成 001 最小文本保存/完整重启闭环，且真实使用对象功能；非空旧目录不得被重新初始化。
4. **Given** 缺库/未知目录或 schema/不兼容对象格式/未完成创建或未知保存，**When** inspect/open，**Then** 零补种/降级/自动恢复；无副作用检查不修对象/投影。若未来要求工作区升级，须另行修订并批准范围及中断恢复验收；本片不交付工作区升级。仅安装库有 FR-026 已确认的窄演进例外。
5. **Given** 合法旧安装及已关闭/未改动的 001 工作区，**When** 当前操作员确认安装升级，**Then** 仅安装 schema 演进，原身份/授权/登记/操作历史保持；未排空或基线变化拒绝，结果不明按原 key 调查，完整重启后仍可使用原 001 工作区。
6. **Given** 安装/工作区有限保留预算已满，**When** 操作员预览并确认受支持的调额，**Then** 正确拒绝无权/陈旧/不安全调整，合法扩容不清理证据或重算旧结果；重启后额度与保留事实一致。

## 4. Functional Requirements

所有 MUST 都是已批准的行为要求，不是当前实现或通过声明。

- **FR-001**：MUST 保持独立 Go Host、同一正式写入 owner；类型与能力按第 2 节/Q1 明确，不通过保存非执行内容启动执行器。
- **FR-002**：每次对象接收/读取、候选、历史、提交、调查与投影命令 MUST 从认证上下文确定当前 tenantId/principalId 和显式 workspaceId，重新检查当前权限及所属资源/版本；请求体、hash、旧引用/receipt 不授予权限。
- **FR-003**：MUST 提供稳定 resourceId、区内版本及区级 revision；一版完整描述其文本与精确对象集合/逻辑名称/长度/摘要；一版不变不代表多资源快照（Q2）。
- **FR-004**：对象 MUST 保存精确原始字节；不得静默改换行、Unicode、编码或二进制零字节；不能只比较文件长度/客户端声明来证明相同。
- **FR-005**：对象接收/就绪、候选、正式引用 MUST 分离；未确认输入不移动正式指针/Head，不产生正式成功公告/receipt。
- **FR-006**：正式引用前 MUST 验证最终字节存在、完整且摘要一致；发布/校验后路径或物理对象被替换不能绕过引用时核验。不得声称数据库事务覆盖文件或未经验证的硬件断电原子性。
- **FR-007**：预览 MUST 展示完整拟保存内容/对象集合/基线，绑定当前工作区、主体、资源、精确输入与 baseRevision/baseDigest；任何相关变更要求新预览/确认，不因只上传新对象自动应用。
- **FR-008**：全新确认 MUST 重新授权、校验候选及基线并持久关联原 key；同原 key 的已有结果调查先于候选过期/旧 epoch/旧基线的新准入判断。确认不得静默合并陈旧候选。
- **FR-009**：正式版本、指针、Head、正式对象引用、唯一 receipt 及保存操作结果 MUST 形成一致正式提交；确认前不得发布成功或允许依赖执行。
- **FR-010**：MUST 保留同区同 key/主体/输入在同一未替换持久历史内至多一次正式效果；改主体/输入/目标复用 key 拒绝，不泄旧内容；跨区相同 key 互不关联。对象物理复用不扩张此保证。
- **FR-011**：MUST 区分确定拒绝、正式已确认、结果 unknown；保留脱敏关联与原 key 查询/显式调查。缺 receipt、孤立对象、超时、断连均不能自动证明未提交或安全重试；调查不重放业务写入。
- **FR-012**：MUST 提供当前及明确历史版本的完整内容与对象字节读取、有界版本列表；当前授权覆盖每次请求；历史旧版不随更新改变，不裁剪正式历史/receipt。
- **FR-013**：MUST 在关闭/新进程重开后从真实持久事实恢复版本、对象引用/字节与原回执；不得依赖旧进程、客户端缓存或投影作为唯一事实。
- **FR-014**：任一已确认版本的正式对象引用缺失/损坏/不一致，MUST 拒绝依赖该对象的完整读取和新正式引用，明确受影响版本及完整性/恢复范围；不得返回少附件的“完整成功版本”、静默替换字节/丢弃坏引用或借投影补种。仅在能可信证明其他操作不依赖该损坏、且正式存储/排他仍可信时，才允许其继续；不能可信确定影响则保守封锁该工作区的新写。未确认对象校验失败只拒绝其候选/引用，除非已有证据影响正式完整性；不得无理由封锁 B。

## 5. Key Entities（业务含义，不预设存储表/API）

- **Resource / ResourceVersion**：工作区归属、稳定资源、不可变完整版本、当前指针及区级 revision；内容边界遵循已确认的 Q1/Q2。
- **Object / VersionObjectReference**：精确最终字节与可验证摘要、长度；正式版本中的授权关联。摘要或接收凭据本身不是访问权或正式引用。
- **Candidate / Confirmation**：非正式拟保存输入、完整对象集合、主体/目标/基线及预览关联；不承诺 M3 通用候选文件工具。
- **SaveOperation / CommitReceipt**：持久原 key、精确输入、主体、资源/版本及正式提交结果；unknown 保留调查，不承诺网络 exactly-once。
- **CommittedProjection**：指定正式版本/对象清单的可再生派生视图及新鲜度/失败信息；不是第二主库或有效授权。
- **DirectoryAccess / PhysicalWork**：当前 epoch、准入/关闭/物理资源与安全边界；业务状态、生命周期、访问模式、逻辑结果、物理收尾、持久性、投影健康分别可观察，不能并成一个 status。

## 6. Measurable Success Criteria

以下全部为**待实现、待实际验证**的验收目标；具体技术 profile 与故障注入点在 plan 冻结，不允许按实现便利降低目标。
