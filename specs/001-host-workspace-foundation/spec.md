# Feature Specification: 独立 Go Host 与目录工作区基础闭环

**Feature Branch**: 未创建功能分支；本地 `master` 无提交，feature 与分支名独立。

**Feature Directory**: `specs/001-host-workspace-foundation`

**Created**: 2026-10-17

**Status**: 需求基线不变；当前功能授权及历史批准统一见[授权记录](<authorization.md>)。规格状态不代表运行验收通过。

**Input**: 用户要求独立 Host、可信本地连接、稳定目录身份、真实工作区数据库、最小正式资源保存/读取、关闭和完整重启重开、排他写者及两区隔离；无效目录不得补种或执行。

治理：[宪章](<../../.specify/memory/constitution.md>)；架构与阶段：[总体范围](<../../docs/scope.md>)。
规格只固定行为，不固定驱动、锁算法、认证介质、路由、表结构或包布局。
Go、Windows 本地文件系统、真实 SQLite 是用户明确约束，不是新推断的技术取舍。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 不启动前端也能安全连接 (Priority: P1)

本机用户启动安装级 Host，经可信本地认证管理其获准目录，不依赖浏览器或旧 Host。

**Why this priority**: 独立后端不能变成旧 Host 转发壳，本机连接不能等于免认证。

**Independent Test**: 不启动前端、旧 Host、Provider、插件，用外部测试客户端启动/认证/断开/重连。

**Acceptance Scenarios**:

1. **Given** 无产品前端及旧 Host，**When** 启动新 Host 并认证，**Then** 能识别安装、当前租户/主体并完成获准目录操作。
2. **Given** 未认证、失效/伪造身份或主体仅获 A 权限，**When** 请求 B 的创建/登记/开关/保存/读取，或篡改目标、资源 ID、请求体身份，**Then** 拒绝且不泄漏 B 内容；拒绝可关联但不回显秘密。
3. **Given** Host 已接收保存，**When** 客户端关闭、断线或取消订阅后重连，**Then** 不当作取消/回滚；用户能按操作关联调查结果，未知结果不自动重发。

---

### User Story 2 - 创建并登记长期目录实例 (Priority: P1)

用户显式创建新目录工作区，获得稳定身份；安装登记仅定位，不复制业务事实。

**Why this priority**: 持久工作区必须有真实数据库，不能仅有空目录或内存对象。

**Independent Test**: 全新合成目录执行 create/inspect/register/open，并对已有目录、残留、未支持位置验证拒绝；只依赖 US1 授权夹具。

**Acceptance Scenarios**:

1. **Given** 获准、全新、空的受支持本地目录，**When** 明确 create，**Then** 建立稳定 workspaceId、一致目录描述与真实数据库，租户/主体归属明确；不会自动授权其他主体。
2. **Given** 已创建实例，**When** 重复登记或检查，**Then** 保持身份、定位与正式事实，不创建第二份可独立修改的业务副本。
3. **Given** 非空目录，**When** create，**Then** 拒绝覆盖，原文件不受损；**Given** 创建中断残留或不完整/损坏实例，**When** open/inspect，**Then** 明确分类并拒绝打开，不猜测完成、不补种。合法已存在的非空工作区按正常检查/重开处理。
4. **Given** 实例已关闭、无挂起操作，**When** 同安装内停机移动合成目录并显式更新获准定位，**Then** 身份和内容不变，旧位置不补种。仅验证身份非路径，不交付通用移动工具。

---

### User Story 3 - 保存正式资源，完整重启仍可读取 (Priority: P1)

用户将最小非执行型文本记录经预览、校验、显式确认保存为正式版本，关闭目录并完整结束 Host 后重开读取。

**Why this priority**: 这是不可删减的真实闭环，不能用健康检查替代或无归属延期给 M2。

**Independent Test**: 在 A 保存合成 r1、按基线更新为 r2，关闭 A、结束 Host 进程，再以新进程重开，逐字段比较身份/版本/内容。

**Acceptance Scenarios**:

1. **Given** A 已授权可写，**When** 提交标题/正文候选、预览校验、显式确认，**Then** 确认前正式状态不变；成功后得到稳定 resourceId、A 归属、正式版本及可核对正文。
2. **Given** 正式 r1，**When** 基于其 revision/digest 确认 r2，**Then** 正式版本前进；旧候选再次提交被拒绝，不覆盖 r2。两客户端持同一旧基线确认，最多一方成功。
3. **Given** 已确认 r2，**When** 关闭 A、完全退出 Host、以新进程重开，**Then** 安装/租户/主体/工作区/资源身份、正文和正式版本保持，不依赖旧内存或客户端缓存。
4. **Given** 保存故障注入，**When** 提交前失败，**Then** 明确拒绝、旧版本不变、无成功公告/依赖执行；**When** 提交后回执丢失，**Then** 客户端见结果未知而非回滚成功，调查后仅有一个正式提交，不自动重试。
5. **Given** 未确认/陈旧候选或直接编辑的候选文件，**When** 客户端关闭、目录重开，**Then** 不自动生效/执行；本片不支持的文件导入/Apply 明确 unavailable。

### User Story 4 - 排他写者与异常退出恢复 (Priority: P1)

用户不能因并发打开或复制目录形成双写；进程退出后必须重新取得真实排他才能写。

**Why this priority**: 锁文件/PID 检查不足以保护正式事实。

**Independent Test**: 两个真实 OS 进程竞争合成 A，分别验证持续持有、同时竞争、正常关闭、异常退出；不以两线程或 Mock 替代。

**Acceptance Scenarios**:

1. **Given** P1 持有 A，**When** P2 请求可写或尝试保存，**Then** P2 拒绝、正式内容不变；伪造/移除普通锁文件不能导致双写。
2. **Given** 两进程同时竞争未打开 A，**When** 申请写访问，**Then** 最多一个成功，不出现两个确认写者。
3. **Given** P1 正常关闭或被强制终止，**When** P2 重试打开，**Then** 只在排他与持久状态验证成立后可写，已确认数据保留；不以 PID 消失/删文件直接宣布安全。
4. **Given** 同安装发现 A 的同身份目录副本 C（含停机复制），**When** 登记/打开 C 可写，**Then** 身份冲突拒绝，不自动换 ID/复制原授权/替换 A。其他安装也不因持有目录自动获权。

---

### User Story 5 - 两区并行，关闭/局部损坏不串区 (Priority: P1)

同一 Host 打开 A/B，各自保存正式内容；关闭或发现 A 损坏不无理由阻断 B。

**Why this priority**: 工作区不是全局 current workspace 下的两个标签。

**Independent Test**: A/B 使用相同显示名与客户端临时键、不同正文交错保存；分别关闭 A 和停机破坏 A，再验证 B。不伪造本片已有 Run。

**Acceptance Scenarios**:

1. **Given** A/B 可写，**When** 交错保存/读取并混入另一区资源标识，**Then** 各自只见所属内容，跨区引用拒绝，无候选/版本/数据串区。
2. **Given** 两区有独立操作，**When** 关闭 A，**Then** A 拒新准入并按实际保存状态收尾，B 可继续保存/读取；关闭不删除或归档 A，重开仍可读。
3. **Given** A 停机后合成损坏而安装安全状态完好，**When** 重开 A/B，**Then** A 拒绝打开/写入，B 不依赖 A 的操作继续成功。
4. **Given** 共享身份/授权持久化结果未知，**When** 操作依赖此共享事实，**Then** 仅保守阻断相关操作并解释范围，不绕过认证；不承诺共享进程完全故障独立。

---

### User Story 6 - 检查坏目录但不改变它 (Priority: P1)

检查损坏/伪造/未来目录时得到明确拒绝，不自动补种、修复、迁移或外部执行。

**Why this priority**: 不以“自动恢复”破坏原数据和身份边界。

**Independent Test**: 合成样本分别缺库、坏摘要、伪造描述/身份、未来格式/schema、旧身份 v1、路径不支持；比较检查前后文件清单/字节和外部调用计数。

**Acceptance Scenarios**:

1. **Given** 上述样本或不存在路径，**When** inspect，**Then** 明确分类；目标零创建、零改字节、零修复/迁移/激活/Provider 调用。
2. **Given** 缺库、坏摘要、伪造 seal、冲突或未来版本，**When** open，**Then** 拒绝，不补默认库、不换身份、不信任正确外观的文件名。
3. **Given** 合法目录但主体未授权、复制品未绑定或无真实排他证据，**When** 请求可写，**Then** 拒绝；历史 DTO、摘要、旧审批、Trust 不产生当前执行权。

### Edge Cases

- 路径别名/大小写/相对路径/junction/reparse/根外路径不能绕过身份、授权、排他；未经验证的形态拒绝，不外推跨平台保证。
- 同名实例/资源、伪造 workspaceId/tenantId/principalId、跨区引用必须有负例，名称不是身份。
- create 中断、零字节库、旧身份 v1 和未来版本不能由 open 补种；现有文件不得覆盖。
- 保存前拒绝、保存中退出、提交后断连区分已确认/已拒绝/未知；未知时不自动重试/派发或宣告移动/备份安全。
- 关闭中保存悬而未决：拒新写，不谎报完成/锁已释放，B 独立操作继续；旧写句柄在关闭完成后不得再提交。
- A 候选错误不等于整个目录坏；本片不消费通用文件候选，报告 unavailable，不默认生效。
- Host 崩溃/磁盘满/断电可能影响 A/B；只验证真实持久边界，不保证 B 持续在线。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：Host MUST 独立启动，公开客户端能完成本片操作；不依赖前端、旧 Host、Provider、插件。
- **FR-002**：本地连接 MUST 认证并使用稳定 installationId/tenantId/principalId；默认不开放远端；引导与认证介质归 plan 验证。
- **FR-003**：每次目录/资源查询与命令 MUST 确定目标 workspaceId 和当前授权；请求体、路由、历史不替代认证，失败不泄漏目标内容。
- **FR-004**：断连/取消订阅 MUST NOT 取消已接收操作或推断回滚；独立取消语义不得混入连接契约。Run 本片不实现。
- **FR-005**：MUST 区分显式 create、只读 inspect、安装 register、open、close；重复登记不复制业务事实或改变身份。
- **FR-006**：create MUST 仅在获准全新空目录建立稳定身份、一致描述和真实数据库；残留须明确拒绝，不由 open 猜测修复。
- **FR-007**：inspect MUST 不创建目标目录/文件、不改字节、不修复/迁移/激活/发 Provider 请求或授予写访问；可输出脱敏安装日志而不写被检目录。
- **FR-008**：open MUST 校验格式/schema、身份/摘要、位置、当前授权；缺库/坏摘要/未来版本/伪造/冲突/不兼容旧 v1 均拒绝，不补种。
- **FR-009**：登记 MUST 仅定位及关联授权；工作区数据库拥有正式事实。移动不换身份，同身份副本不能第二可写；目录/摘要/旧审批不自动授权。
- **FR-010**：目录格式、数据库 schema、公共协议 MUST 分别版本化；完整业务目录不伪装旧身份 v1，具体编号归 plan/research。
- **FR-011**：MUST 提供最小非执行型文本记录：稳定 resourceId、workspaceId、标题/正文、正式 revision/digest、提交关联；不引入 Agent/Workflow/页面执行。
- **FR-012**：保存 MUST 经 Host 授权、候选预览、有效性校验、显式确认才正式生效。确认绑定目标/内容/baseRevision/baseDigest；变更后重新预览确认。
- **FR-013**：MUST 可读当前正式内容/版本/归属；更新绑定基线，陈旧/并发冲突拒绝，不自动覆盖；不承诺通用历史浏览/回滚工具。
- **FR-014**：MUST 真实落盘；完整关闭并结束进程后重开，安装/主体/工作区/资源身份及版本/内容保持，不靠内存或浏览器缓存。
- **FR-015**：MUST 区分确认提交、拒绝、结果未知，并提供脱敏关联及调查能力；成功公告/依赖执行不得先于保存确认，未知不得当回滚/安全重试。
- **FR-016**：若使用对象文件，MUST 在正式引用前验证最终字节与摘要；不使用时不得用空文件伪称对象协议完成。完整对象/投影机制归 M2。
- **FR-017**：直接编辑候选文件 MUST NOT 改变正式状态/执行。本片只做最小记录命令预览/确认；通用文件导入/Apply、Build/Studio 明确 unavailable。
- **FR-018**：同目录 MUST 最多一个实际可写 owner；真实第二进程/同时竞争拒绝第二写者，锁文件/PID 不构成充分证据。
- **FR-019**：释放或异常退出后 MUST 重获真实排他并检查持久状态才开放写入；未知未解决不宣称排空/关闭安全。
- **FR-020**：close MUST 拒绝该区新准入，等已接收保存达到安全边界或报告仍排空/未知；不删除、归档或关 B；完成后旧写句柄不可提交。
- **FR-021**：同 Host MUST 至少同时开两个独立工作区数据库；数据/候选/版本/对象归属不串区，关 A 后 B 可继续保存/读取。
- **FR-022**：A 局部损坏/不支持/资源错误 MUST 只阻断对应范围，B 独立操作继续；共享安全事实未知时只阻断真实依赖项并解释，不绕过不变量。
- **FR-023**：对外状态 MUST 分离业务状态、目录生命周期、访问模式；inspect 不等于只读 open 或业务就绪，归档/损坏/关闭不得混同。
- **FR-024**：MUST 保留 Run 逻辑状态/物理收尾/持久化分界与安装总容量约束，但不伪称首片已有 Run；执行/资源隔离验收归 M4/M5。
- **FR-025**：MUST 声明共享进程崩溃/资源耗尽/磁盘满/断电可能影响多个区；不实现逐区 Host 进程，不把子进程/cwd/Trust 当 OS 沙箱。
- **FR-026**：MUST 有脱敏关联及可区分拒绝：未认证/授权、路径不支持、未完成目录、版本不支持、缺库/损坏/摘要、身份冲突、写者占用、陈旧候选、关闭中、提交未知；编码归 plan。
- **FR-027**：验收 MUST 使用全新合成目录/记录，日志不泄密或入 Git；空目录/健康检查/Mock/测试定义不代表完整交付。
- **FR-028**：MUST 禁止本片自动导入旧库/凭据、续跑未知副作用、真实 Provider/插件、跨区业务协作；不造空消息总线/通用插件框架。

### Key Entities *(include if feature involves data)*

- **PrincipalContext**：安装/租户/主体及当前授权，不是请求体任意声明。
- **WorkspaceIdentity**：稳定长期实例身份；路径、名称、副本不构成身份或授权。
- **DirectoryRegistration / DirectoryAccess**：身份到允许位置的关联，以及独立生命周期/访问模式/排他证据/拒绝原因；不是业务事实副本。
- **TextRecord / Candidate**：最小非执行型正式记录及待确认内容/基线，彼此分离。
- **CommitOutcome**：与主体/工作区/候选绑定的提交关联和已确认/拒绝/未知结果，不是可重放许可。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：无前端/旧 Host/Provider/插件时，独立客户端完成创建、预览确认保存、读取、关闭、完整停机重启重开，全部必测步骤成功。
- **SC-002**：A/B 各保存至少10条不同正文，交错操作并各更新至少1条；完整重启后全部身份/版本/正文相符，零串区、零已确认丢失。
- **SC-003**：持续持有、同时竞争、异常退出三类场景各重复至少10次；任何时刻最多一个写者，失败者零成功保存，退出后只在安全边界重获写入。
- **SC-004**：未认证/失效身份/无 B 权限/伪造归属/跨区引用负例全部拒绝，零目标内容泄露、零越权修改。
- **SC-005**：关闭 A、停机损坏 A 两种场景，B 均能新增/更新/读取至少一条；共享安全未知时依赖操作被解释性阻断，不宣称完全故障独立。
- **SC-006**：缺库/坏摘要/伪造身份描述/未来目录/未来schema/不兼容旧v1/不存在路径每类至少1例；inspect前后目标清单/字节不变，零补种/迁移/激活/Provider调用，open对不兼容样本全部拒绝。
- **SC-007**：保存前拒绝、基线冲突、提交后丢回执、保存中断每类至少1例；结果符合旧正式状态/唯一正式提交/未知边界，零未确认成功公告、零自动重复提交。
- **SC-008**：同旧基线并发更新、同身份复制目录各至少1例；前者最多一方正式成功，后者零第二可写实例；停机移动身份不变、不继承新授权。
- **SC-009**：断连、关闭中保存悬而未决、旧句柄再写每类至少1例；不从连接推断回滚，不谎报关闭安全；关闭后旧写句柄拒绝，各状态维度可分别观察。

## Assumptions

- 经 plan 验证固定的 Windows 本地文件系统、单安装/单机本地主体、全新目录和合成数据；不默认网络盘/云同步/多Host协同写。
- **用户澄清确认**：最小资源为非执行型纯文本记录，先证明正式持久闭环，不引入 Agent/Workflow/页面运行；技术驱动和锁不作为用户选择题。
- 只读检查由 inspect 实现；持久只读 open/并发只读连接不是本片承诺，但访问模式仍明确，inspect 不能冒充打开。
