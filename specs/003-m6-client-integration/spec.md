## 2. 问题、目标与范围

Host已有独立内核和公共协议，但尚无已验收的浏览器产品入口、当前主体可见工作区集合及React组合闭环。结构操作存在不等于对应能力可用；以浏览器绕过原生认证、直接写库或让桥代替业务owner，不是M6。

目标：本机owner/operator通过可信交付的React客户端完成“可信连接/重登记 → 当前身份与能力 → 授权工作区发现/选择 → 必要的显式打开 → 读取 → 文本候选预览 → 明确确认 → 匹配receipt或原key调查”；第二个独立消费者用同一Host公共业务协议完成相同业务并互证正式事实。

## 3. 优先用户场景与可观察验收

以下故事规定用户应得到的结果，保留全部既有验收约束；它们不是逐项运行通过声明，也不再笼统称全部尚未实施。Q1–Q3产品边界已澄清；工程/接收/联合各层证据及未验范围见tasks，当前阶段限制见统一授权记录。

### US1 · 可信进入与重新登记（P1）

作为本机安装owner/operator，我要知道自己进入了哪个可信安装/活实例及当前会话，而不向浏览器暴露Host秘密。

1. 给定合格的专用浏览器、已初始化的合成安装及可核验Host，用户明确连接后取得当前身份/能力；可信页面与每个实际携带bearer的Host连接均关联正确活实例。页面不直接读安装私有文件或Host bearer。
2. 给定多个候选、错误服务、端口复用、实例替换、不可达或过期，入口拒绝含混关联并展示可行动的状态；重新登记必须重新核验，旧上下文不得悄然绑定新实例。PID、端口或installationId任一单项都不是活实例证明。
3. 给定未初始化、损坏或不支持的安装/浏览器/profile，不自动初始化、修复、降级或返回假数据。允许用户显式启动同一已初始化安装中尚未运行的Host；不能据此自动初始化、修复或重启。

### US2 · 当前授权发现、切换与显式打开（P1）

作为当前主体，我要只看到Host允许的工作区，并在切换时不混入旧身份或旧区结果。

1. 授权集合由Host交付；空集合为合法空状态。分页、失效及查询迟到均不泄漏无权B的存在/内容；已知B的ID不提供额外权限。合成受限身份仅作安全测试，不代表产品受限签发已交付。
2. 选择已关闭A不自动open、create或register；用户明确打开时取得Host认可、绑定目标/用途的前置快照，保留该次确认基线。基线陈旧则拒绝并要求重新检查/确认，不能偷偷换成最新CAS值。
3. A/B切换、会话/主体变更、连接代次或epoch改变后，迟到响应不进入当前查询快照或驱动当前动作；原操作调查线索另行保留，不能仅因epoch变更丢弃。

### US3 · 文本预览、确认与正式结果（P1）

作为用户，我要先预览再确认，并知道“保存确认”和“界面交付失败”是两回事。

1. 预览不写正式资源。确认绑定原安装、主体、工作区、候选与基线；收到有效、匹配原操作且确证正式提交的Host receipt后才显示保存已确认。客户端不另算一套可替代Host的正式结果。
2. 有效OperationView表明committed且附匹配receipt，即便HTTP为202并标记viewDeliveryFailed，也保持保存已确认，独立提示交付失败，不重存。仅202 accepted、缺receipt、结构/作用域不匹配或截断响应均不得冒充确认。
3. 另一消费者在预览后修改基线，确认必须陈旧拒绝并要求新预览，不能自动合并/覆盖。一次用户确认不能因双击、页面重挂载或底层透明重试造成第二次业务转发。

### US4 · 传输不确定与原key恢复（P1）

作为遇到超时/断线的用户，我要安全调查原操作，不被“重试成功”的幻象误导。

1. RST、超时、截断或无效响应只说明客户端未取得可信完整结果；显示传输结果未确认，不擅自将Host业务persistence改成unknown/rejected。业务unknown只由Host证据表述。
2. 保留原安装/主体/工作区/operation key与必要输入关联，按当前授权查询原key；需要打开或显式reconcile时遵守Host原有门。切区、刷新、重认证不换key自动POST；查不到、历史不可用或期限到达都不表示可安全重试。
3. 路由/页面刷新及同桥重登记须隔离旧响应且保留可验证线索。桥/浏览器冷重启后的恢复保证见Q3；原身份未确认前不恢复，缺可信线索时明确不可恢复、不猜测key或捏造业务终态。

### US5 · 第二消费者与实际生命周期（P1）

作为同时使用React与独立客户端的用户，我要两端读到相同正式事实，而关闭页面不会停掉别人的工作。

1. CLI写入后React读到同一版本/receipt，反向亦然；两端全部经同一公共业务协议和当前授权，不直写库/对象或依赖私有客户端写者。
2. 保存已accepted时取消等待、关闭页面或退出专用浏览器，仅结束该等待/连接；另一消费者继续使用B。Host不因此停止，A锁不因页面消失释放。显式close期间显示draining，实际排空/结果门满足后才显示closed。
3. Host真实正常停止后，以新进程、新连接登记及新epoch重开；保存receipt仍按原key可核验，易失close协调历史缺失不伪造close成功。强杀不显示正常排空或自动重放。

### US6 · 可信页面、安全拒绝与可发布组合（P1）

作为用户，我要受支持且权利清晰的客户端，不以放宽Host安全换取“能用”。

1. 不同端口恶意页即使浏览器发送了某cookie，也不能通过fetch/form/preflight驱动Host业务。真实同源正控可用；错误Origin/authority、CSRF、Fetch Metadata、活实例关联缺证均拒绝。
2. 会话过期、实际撤销或重登记失效后，拒绝该旧上下文的新准入及迟到视图交付；已accepted业务仍按Host原状态推进/调查。浏览器会话退出与Host会话撤销的确认边界见Q2，不承诺尚无协议的瞬时撤销。
3. 使用固定Host、统一契约、真实React生产包及可信原生层进行组合验证；不支持profile/能力显示unavailable。深链接/静态fallback不吞API/认证/错误；许可未闭合的旧UI只能内部隔离验证，不正式迁入或发布。

## 4. 功能需求

- **FR-001 [US1,US6]**：Host是唯一业务、权限、执行、数据库与正式操作结果owner，且可不依赖React/浏览器启动。桥/客户端不得写正式库、签发业务权限、自造receipt或保存第二份业务终态。
- **FR-002 [US1]**：可信启动/发现/登记须关联指定安装及活实例，覆盖已有实例、候选含混、不可达、未初始化、不支持和实例替换；新实际bearer连接及连接复用都须保持关联证据，缺证fail closed。允许用户显式启动同一已初始化安装的Host，不自动初始化、修复或重启；提供仅结束当前客户端会话的显式退出，不停止Host或撤销其他客户端。
- **FR-003 [US1,US6]**：renderer、URL、普通日志/错误、浏览器存储、构建变量/产物不得出现Host bearer、原生凭据或私有安装定位信息。桥会话/CSRF与Host session严格区分；不以浏览器侧凭据代替Host授权。
- **FR-004 [US1,US6]**：仅可信发布的页面在专用干净浏览器环境内接入；可信页面交付、精确Origin/authority、Fetch Metadata、独立CSRF与活连接关联共同保护边界。承认Cookie不按端口隔离；不能只靠端口、CORS或cookie属性。
- **FR-005 [US1,US6]**：桥仅暴露首片有限动作，不提供任意URL代理、任意路径/文件访问或通用命令；不向Host转发浏览器Origin/Cookie，不放宽Host原有HTTP防线。有限allowlist不等于owner token被衰减，也不证明恶意原生代码隔离。
- **FR-006 [US1,US2]**：身份、可见工作区与运行能力由Host按当前授权给出；集合有界分页/失效且空集合有效。不得借错误/搜索/分页枚举无权目标或凭路由、自报ID、旧缓存推断授权。
- **FR-007 [US2]**：选择与打开分离；合法open前置由Host交付，绑定安装/主体/目标/用途及快照版本，执行再授权/CAS。陈旧则拒绝，不能静默更新用户基线；不自动create/register/relink/repair。
- **FR-008 [US2,US4]**：查询快照按安装、主体、会话/连接代次、工作区及活epoch隔离，迟到结果不能污染另一范围；旧结果不可驱动新写准入。调查线索不依赖易失查询缓存存活。
- **FR-009 [US2,US3]**：草稿/偏好与正式状态分离；草稿不自动提交，查询缓存不持久化为业务库，不提供离线mutation队列。表单内容不擅自改变Host字节/摘要语义。
- **FR-010 [US3]**：预览与确认分离；确认使用Host认可的候选、baseRevision/baseDigest及原key关联，当前授权/基线/epoch由Host重校验。无确认或陈旧不得写正式版本；不伪造合并。
- **FR-011 [US3,US4]**：成功判定核验Host完整结果、原安装/主体/工作区/操作匹配及正式commit证据。200/201/202均不单独证明保存；202+committed+有效匹配receipt必须保留保存确认，viewDeliveryFailed独立表述且不得再save。
- **FR-012 [US4]**：客户端传输未确认与Host逻辑/持久/物理三轴分离；不得把超时/RST/截断映射成回滚、业务unknown或safe-to-retry。无可信完整结果时仅沿原key调查。
- **FR-013 [US3,US4]**：UI、消费库、桥和底层传输均不得自动重试正式POST、换key重发或在请求不明时重新准入。重复点击/页面重挂载须有有界传输围栏；围栏不是业务结果库，超时/淘汰不赋予重发权，不能因容量不足绕过Host安装总量。
- **FR-014 [US4]**：恢复前验证原身份及当前授权，保留原key/目标/必要输入关联；GET调查及显式reconcile仅按既有Host语义，不重放原业务。missing/unavailable/unknown与明确rejected分别展示，任何缺失不等于已回滚。
- **FR-015 [US4]**：刷新、换区、重新登记不擅自丢弃未确认操作线索或把其挂到新安装/主体；线索不能恢复时明确说明边界。浏览器或桥正常冷重启后必须持久保留并找回未确认保存的最小非授权调查线索；重新核验原身份和当前权限后才查询原操作，不保存第二份业务终态，不自动重发。不承诺磁盘损坏、手动删除或卸载后恢复；容量不足不能静默丢弃未确认线索或放行无法保留线索的新保存。具体机制留待设计。
- **FR-016 [US5]**：React与第二独立消费者使用同一公共业务契约、授权和提交owner，能互读正式版本/receipt并产生真实基线冲突；仅“两个页面”或两套私有写端口不满足。
- **FR-017 [US5]**：关闭页面/连接/取消等待不取消已accepted业务、不停止Host、不释放区锁；显式close与Host停止遵守真实排空/unknown门。A局部关闭/故障不无理由终止B，实际共享授权/持久化不可信则诚实说明共享围栏。
- **FR-018 [US1,US6]**：过期、实际撤销、实例替换使旧会话/连接上下文失效；新请求与视图交付均检查当前状态。浏览器断开、Host会话撤销及已accepted业务不混为一件事；显式退出立即阻止当前客户端新请求，只有Host确认对应会话结束后才显示“Host会话已撤销”，否则显示待确认；不取消已accepted业务，不承诺瞬时撤销；退出作用于该当前客户端会话的所有页面：均不得继续准入或接收迟到视图交付；独立客户端会话不受影响。关闭页面本身不等于主动退出。该入口尚待实现与验收。

## 6. 可衡量成功标准（全部待验收）

- **SC-001 [US1,US5]**：同一固定组合中，React与独立消费者分别创建/更新A/B各3条合成文本，双向读取当前正式文本并核对当前版本标识/原保存receipt一致；每次创建或更新后逐次核对当时的当前内容、版本标识与原保存receipt，不要求读取旧版正文；Host实际正常结束后新进程重新登记/显式open，当前正式内容、版本标识、原保存receipt与身份/新epoch证据匹配，不依赖历史版本读取。预览期间正式head/行数无变化。
- **SC-002 [US2]**：A-only合成身份、无授权及owner正控各覆盖有结果/空集合/分页；B不在未授权结果和错误中出现，已知B的直接读取/预览/确认/原key调查全部拒绝且A/B正式事实不变。
- **SC-003 [US2,US4]**：分别跨安装、主体、会话/连接代次、工作区和epoch制造迟到响应；5类均不污染当前视图或触发写入。原操作线索仍指原范围，重登记前不恢复旧身份上下文。
- **SC-004 [US3]**：分别验证200有效receipt、202 committed+匹配receipt+viewDeliveryFailed、202仅accepted无receipt，以及错误作用域/截断receipt。前两类显示保存确认（视图失败独立），其余不得显示成功或自动重存；查询原key与正式DB事实一致。
- **SC-005 [US4]**：真实RST、成功响应截断、超时各至少3次，关联原用户确认/key，保留消费适配、桥及实际Host连接的正式POST发送和正式版本证据；首发后的自动再次发送及新key为0，只按原key调查，不能仅凭唯一版本或Host去重判通过。传输故障不能被记作已发生DB COMMIT unknown；后者另用真实Host故障证据验证诚实状态映射。
- **SC-006 [US3,US5]**：健康固定profile下React与第二消费者持两份同base合法候选竞争10轮，每轮恰1次正式确认、另1次陈旧拒绝，唯一receipt/版本与两端查询相符；不引入故障/重试来制造胜出。无进展或设施异常单列失败/未验，不计通过轮。
- **SC-007 [US3,US4]**：重复点击、页面重挂载及真实底层会触发透明重试的故障/条件各至少3次，关联原确认/key并观察消费适配、桥及实际Host连接的正式POST发送证据；首发后自动再次发送为0，每个原用户确认不发生第二业务转发/新key，不能仅凭唯一正式版本或Host去重判通过。围栏满额或证据丢失明确拒绝/不可恢复，不自动放行。
- **SC-008 [US5]**：真实已accepted且物理调用未结束时，分别取消等待、关页面、退出专用浏览器；三类均保留Host/锁/原操作直到实际结束，B仍可创建/更新/读取。显式close期间不谎报closed，实际结束后正常重开/原receipt匹配；进程强杀不记正常排空。
- **SC-009 [US1,US6]**：可信页面正控外，实际跨端口cookie发送、fetch/form/preflight、错误Origin/CSRF/Fetch Metadata/authority、错误/替换服务与连接复用均有负例；拒绝分支不进入Host业务dispatch、不泄漏bearer，全部实际bearer连接具备正确活实例关联证据。
- **SC-010 [US1,US4,US6]**：实际会话到期、真实Host撤销及实例替换各验证新请求拒绝、迟到响应不交付、原已accepted结果不被伪造取消；同桥刷新/重认证按原身份/key恢复。显式启动已初始化Host须有成功正控及未初始化/损坏/实例含混拒绝负例；当前客户端退出须覆盖撤销已确认与未确认两种结果，其他客户端和Host继续可用。分别在未确认保存后正常退出并重启浏览器、正常退出并重启桥，找回原最小线索，经原身份和当前权限重验后调查原操作；身份不匹配或无权时拒绝调查，自动再次保存/换key均为0。损坏/删除造成线索不可恢复时明确提示，不猜业务结果；不将此例计为正常冷重启恢复通过。另验证最小调查线索持久化失败及容量不足两类拒绝：新保存向Host正式提交的转发次数为0，已有未确认线索不被新操作挤掉且仍可调查；正常冷重启后重复点击原操作，保存再次发送和换key均为0。当前会话退出覆盖同会话多个仍打开页面：全部拒绝新准入和迟到视图交付；独立客户端会话仍可正常使用。仅关闭页面不作为主动退出或Host会话已撤销的证据。
- **SC-011 [US1,US6]**：对真实浏览器可见响应、URL/存储、静态产物及普通日志/诊断扫描所有合成Host bearer、原生凭据和私有定位值，泄漏为0；不同桥/Host会话及CSRF负例不能互换授权。不能用删除日志或Mock扫描代替。
- **SC-012 [US1,US6]**：固定生产组合完成绑定漂移/既有字节行为、两消费者联合业务、受支持/不支持profile与能力、深链接/API错误隔离、键盘/focus/主题及错误提示验收；来源/许可未放行时发布状态仍blocked。记录精确源码/契约/工具/产物和运行环境，不以三个旧实验拼成通过。
