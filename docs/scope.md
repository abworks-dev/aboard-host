# Aboard Host — 总体范围与唯一路线

**状态**：proposed/designed；未验证目标不等于已实现架构。当前001功能授权与历史批准仅见[授权记录](<../specs/001-host-workspace-foundation/authorization.md>)。
本文件是总体范围、目标目录、阶段路线的唯一维护位置；功能行为由各 Spec Kit spec 拥有。
治理见 [宪章](<../.specify/memory/constitution.md>)，旧能力证据见 [迁移基线](<migration-baseline.md>)。

## 1. 产品与长期实例

Aboard Host 是本地优先、使用 Go 的独立工作区后端。共享一套引擎，一份目录承载一套长期业务工作区；
目录组织资源、插件、配置、业务数据与运行历史，客户端可以替换。
工作区不是侧栏分组、单个 Agent home、浏览器缓存，也不是每目录独立打包整套服务。

同一工作区保存稳定身份、正式资源及版本、插件组成、配置、业务数据、Agent/Workflow/Session/Run/历史、
明确保存的 Build/Studio 成果。关闭客户端或 Host 不应把工作区当临时会话丢弃。
Host 不依赖前端启动；React/Vue/CLI/桌面客户端经公共协议接入。现有 React 在后续阶段连接，不是启动前提。

## 2. Owner 与目标架构（designed，尚未实现）

采用 Go 模块化单体与端口适配器边界，不采用微服务。

| 边界 | 拥有的事实/职责 | 不拥有 |
| --- | --- | --- |
| 安装级 Host | 安装身份、认证/账户设置、凭据/密钥、包准入与可信缓存、目录登记、当前机器授权、执行/容量/生命周期协调 | 第二份可独立修改的工作区业务副本 |
| 工作区 | 稳定身份、正式资源/配置/版本、插件组成/依赖、业务数据/Build 成果、Session/Run/事件/审计、对象引用/候选基线 | 随目录自动继承的有效执行授权 |
| 客户端 | 展示、交互、声明式渲染、查询缓存、非业务界面状态 | 数据库、密钥、插件实现、任意服务器文件系统的直接访问 |
| 受控执行器 | 按需 Node/Python/原生工具的工作执行及受限回执 | 第二授权者、独立业务数据库写者 |

一个正式事实只有一个当前写者；禁止两个 Host 同写，也禁止 Go 永久转发到拥有全部事实的旧 TS Host。
跨仓协议必须有一个明确权威来源，再生成/验证语言绑定，不能手写两套独立 Go/TS 契约。

## 3. 技术方向与验证责任

- Go 固定受支持版本。2026-10-17 官方下载索引的最新稳定版为 **go1.27.2**，作为首期工具链目标固定值；本机为 go1.27.0，尚未升级或编译验证。进入 plan 时若更新固定值必须记录原因与证据，不隐式使用 latest。
- 标准库优先 HTTP 查询与命令，SSE 事件；只有确需时才采用轻量路由。
- 真实 SQLite，版本化 SQL migration；JSON Schema/OpenAPI 明确跨语言契约。
- 不可变对象文件保存最终字节，数据库保存引用、摘要与正式状态。日志结构化、脱敏、可关联。
- **待技术验证**：SQLite 驱动/事务与持久性设置、Windows 文件系统及跨进程锁、凭据存储、本机可信连接的引导/认证机制、发布方式。
- 不引入 Redis、通用消息中间件、Kubernetes、分布式事务框架或无实际消费者的通用插件基础设施。

Go 版本依据：[官方发布索引](<https://go.dev/dl/?mode=json>)、[发布与支持政策](<https://go.dev/doc/devel/release>)。
Go module path 尚无真实仓库来源；其前置依据按[授权记录](<../specs/001-host-workspace-foundation/authorization.md>)处理，不从旧仓remote推定。

### 3.1 长期数据策略与单一实现范围（designed，未实现）

**SQLite 是本地工作区的长期默认存储实现，不是所有未来部署形态永久唯一的数据库。** 当前只选择一种本地存储方案，不建设多数据库兼容、动态切换或双写体系。完整产品采用每区 SQLite + 不可变对象文件；M1 的最小文本直接入库，不提前建立对象文件或空对象目录。安装库只保存安装事实，不汇总成第二份可修改的工作区业务库。

本节拥有长期数据策略及延期边界；[001 数据模型](<../specs/001-host-workspace-foundation/data-model.md>)只细化首片实体与协议，[001 计划](<../specs/001-host-workspace-foundation/plan.md>)负责本片取舍和验证，不另建第二路线。

| 数据类别 | 长期归属与演进约束 | M1 范围 |
| --- | --- | --- |
| 正式业务事实 | 每区 SQLite 保存正式状态、版本、关系、操作回执与对象引用；只有 Host 正式提交路径可写 | 最小文本、不可变版本、Head、保存回执及必要审计；不预建未来业务表 |
| 候选与输入 | 候选不自动成为正式事实；关联基线并经预览、校验、显式确认 | Candidate 入本区库；不实现通用文件导入/Apply |
| 大型附件与最终字节 | 对象文件保存字节，数据库保存正式关联与摘要；须先验证字节再提交引用 | 不使用对象；完整协议归 M2 |
| 执行历史与业务事件 | 按工作区归属，与临时进度区分；保留、重放、裁剪规则须在消费方功能中明确 | 无 Run、SSE 或事件平台；不得将保存审计冒充执行历史 |
| 投影、搜索索引与缓存 | 可重建，不承载唯一事实；跨区聚合必须重新授权，不成为跨库写入 owner | 不实现投影、搜索、向量索引或聚合服务 |
| 安装身份、有效授权与秘密 | 由安装级拥有；当前授权不由目录副本、旧记录或默认备份继承 | 按 M1 安装安全设计；不实现凭据可移植性 |

长期必须保持以下边界，具体机制由对应阶段验证：

1. **分别版本化**：目录格式、安装/工作区数据库 schema、公共 API 独立演进；migration 有有序版本、校验和与状态记录。M1 只初始化全新 schema 及 ledger、验证一致性和拒绝不支持版本，不交付已有业务 schema 升级/降级器；inspect/open 不自动迁移。未来升级须显式准入、排他/排空、兼容检查及中断恢复；失败不删库重建，不靠旧 binary 直接打开新 schema 回退。
2. **业务与驱动分离**：用例依赖有业务语义的存储能力，SQLite SQL、连接、PRAGMA 和驱动错误映射留在适配器。可使用有价值的 SQLite 特性，不为了未知数据库降到最小公共能力；不造通用 CRUD Repository，不承诺零成本换库。
3. **写入与查询边界**：单一正式写入 owner 是长期不变量；单连接、DELETE/EXTRA 是 M1 待验证策略，不是永久约束。长任务、订阅不持有长期数据库事务；未来读连接、WAL、分页/索引或归档须按真实负载验证，不在 open 时静默改变已有目录协议。
4. **对象与快照一致性**：后续对象发布、引用、GC、备份必须共享清晰的生命周期门和保留规则；SQLite 事务不覆盖外部文件，SQLite 快照也不等于完整工作区备份。恢复须核对数据库 revision、对象清单/摘要、格式/schema 和回执历史；恢复旧快照不能据缺失回执推断可安全重放，不能恢复活授权或未知副作用自动续跑。
5. **跨区与资源边界**：跨区协作由目标 owner 授权并提交，不依赖跨数据库原子写事务；聚合索引可重建。活跃连接、查询、执行和存储维护受安装总容量及每区边界约束，拆库不等于无限资源或进程故障隔离。

| 延期项 | 归属/重新进入条件（不是本轮实现承诺） |
| --- | --- |
| 完整对象发布、引用与投影协议 | M2；证明对象先于引用、提交未知及投影失败边界，不削掉 M1 文本持久闭环 |
| Run 历史、业务事件订阅/恢复 | M5；与执行、授权、保留期、背压及实际收尾一同定义 |
| 工作区快照、备份恢复、移动/克隆工具 | M7；排空/未知结果门、对象保留、历史替换及身份/授权边界验证；M1 仅定义约束，不交付工具 |
| 已有业务 schema 升级、归档/历史裁剪、专用搜索/向量索引、WAL/有界读连接优化 | 有对应消费者或实测负载后在所属功能明确规格、兼容和恢复验收；不自动清理回执或原始正式事实 |
| PostgreSQL、服务端工作区、多机写者、动态多数据库切换 | 当前 deferred、非默认支持；只有产品明确要求多机同区写入/服务端高可用，或本地方案经索引/查询/维护调整仍不能满足已批准容量门时，另立 Spec Kit 功能重评 owner、授权、事务、协议与迁移；不以共享网络目录代替设计 |

换前端、增加插件/Agent、增加工作区或单纯数据量增长，均不自动触发换库。存储演进必须有可重复的容量/延迟/资源证据或明确的新部署需求；未定义/测量的 SLA 不作为已满足事实。上述设计不授予任何新阶段实现、真实数据迁移或远端副作用权限。

### 3.2 平台边界与当前隔离审查（partial；2026-10-18 静态截面）

长期目标包含 Windows、Linux、macOS 的独立 Host；**平台支持是分别验证的安全/持久性 profile，不是更换前端或设置 GOOS 即自动获得的能力**。公共业务身份、资源、提交/unknown、授权与目录生命周期不变量保持一致；路径定位、物理对象身份、锁/排空、私有目录、秘密保护、本机可信连接与存储持久性机制由平台适配器承担。只为实际消费者提取最小能力，不预建通用平台框架，不把 Windows 句柄、SID 或 POSIX 文件描述符变成业务端口/公共 DTO。

本次仅检查现有源码、契约、安装 schema 与工具入口，未执行构建、测试或原生平台验收；不修改001范围、授权、任务/证据或当前 Windows 实现。当前结论是 **部分隔离，尚未完全解耦**：

| 检查边界 | 当前证据与判断 | 跨平台阶段的最小处理 |
| --- | --- | --- |
| 工作区用例模型与摘要 | [工作区模型/读端口](<../internal/workspace/model.go#L19-L73>)不引入 Windows API；[身份摘要](<../internal/digest/digest.go#L143-L151>)使用固定协议相对路径，非 OS 路径；这些已检查部分保持平台中立，不代表完整 Host 可跨平台运行 | 保持物理定位与字节摘要分离，增加 POSIX/Unicode 定位夹具，不用系统分隔符、大小写或 Unicode 归一化改写既有摘要 |
| 文件与锁原语 | [Windows 适配器](<../internal/platform/windows/directory_windows.go#L1-L43>)用构建约束隔离 Windows/amd64，内部持有句柄和 NTFS 物理身份；未提供 Linux/macOS 实现 | 分平台验证锁竞争/退出释放、路径替换/链接/大小写、目录权限及实际排空；不能把 Windows share-deny 语义直接等同 Unix advisory lock |
| 安装与 inspect 串联 | [安装 owner](<../internal/installation/store.go#L1-L35>)直接持有 Windows Lease/File 并读取 SID；[inspect](<../internal/workspace/inspect/inspect_windows.go#L1-L20>)直接依赖 Windows 原语，尚非可替换平台端口 | 为实际安装/目录消费者抽出有语义的最小能力及平台装配；保留句柄固定、无源写、未知关闭不释放等保证，不能只移除构建标签 |
| 安装事实与本机绑定 | [安装 schema](<../internal/storage/sqlite/migrations/installation_001.sql#L12-L40>)包含 windows_sid 与固定16字节 root_file_id；[初始化输入](<../internal/storage/sqlite/migration.go#L58-L65>)也携带 WindowsSID；这是安装事实的 Windows 耦合，未见其进入[工作区身份表](<../internal/storage/sqlite/migrations/workspace_001.sql#L12-L22>) | 在所属功能设计安装 schema/平台绑定的版本化演进，不把 SID 当跨平台 principal，不复制安装授权/秘密；本轮不改既有 migration、ledger 或校验和 |
| SQLite 与持久性 | [存储 profile](<../internal/storage/sqlite/profile.go#L69-L87>)显式仅接受 windows/amd64、win32 VFS；[其他平台 guard](<../internal/storage/sqlite/flush_guard_other.go>)返回 ErrProfile，不静默回退；虽在存储适配器内，尚未拆成平台 profile | 分平台选择并验证 URI/VFS、刷写/同步、提交失败/unknown、物理关闭及完整重启重开；保留 Windows 兼容补丁与负例，不能通过删 guard 假称支持 |
| 公共契约 | [001 引导策略](<../contracts/openapi.json#L14-L18>)要求 SID 校验 named pipe，[定位描述](<../contracts/openapi.json#L2586-L2593>)要求本地 NTFS；这是 Windows 首片的行为语义耦合，不是发现 Windows 原生类型泄漏到 DTO | 在同一契约权威下明确平台 profile 与兼容边界，保持稳定业务身份及当前认证/物理路径核验；修改权威后按原流程生成绑定，不手改生成物或弱化001安全要求 |
| 构建与验证入口 | [runner](<../tools/go.ps1#L10-L35>)无条件设置 windows/amd64 并准备 Windows libc 兼容构建；[协议漂移测试](<../internal/protocol/strict_test.go#L15-L28>)固定调用 python；共享[模块声明](<../go.mod>)未永久 replace 到本机补丁目录 | 增加显式目标/profile、分离交叉编译与原生测试，仅 Windows 目标启用对应兼容准备；明确 Go/Python 工具入口与原生验证矩阵，不扰动001现有 runner/证据 |

这些是后续移植切口，不将 Windows 首片或尚无 Linux/macOS 实现判为001行为缺陷。后续业务核心/公共 DTO 不应继续扩散平台类型；必须接触 OS 的能力保持在对应适配器。**可编译、build tag 或适配器名称只证明各自边界，不证明安全等价或运行支持。**

以下为**完整产品目标**，本轮不创建空业务目录，M1 只实现首片明确需要的部分：

客服工作区/
├── aboard.workspace.json
├── configs/
├── resources/
│   ├── agents/
│   ├── workflows/
│   ├── pages/
│   ├── knowledge/
│   └── skills/
├── plugins/
│   ├── packages/

├── attachments/
├── build/
├── data/
│   └── workspace.sqlite

    ├── objects/
    ├── staging/

| 载体 | 规则 |
| --- | --- |
| 工作区数据库 | 正式业务状态、版本、引用、历史的权威；不得开第二主库 |
| 不可变对象 | 原始最终字节；正式引用前验证存在与摘要 |
| configs/resources | 明确保存或签出的候选；文件变化不直接驱动运行，须预览/校验/显式 Apply |

| attachments | 待导入输入；不自动执行，不自动成为正式资源 |
| cache | 可重建，不能保存唯一事实 |
| 安装登记 | 负责定位目录，不复制可独立修改的业务事实 |
| 凭据与有效执行权 | 默认不随目录移动/复制/备份；当前机器授权须独立检查 |

旧 v1 只提供严格身份基础。完整业务目录必须独立版本化；**proposed：评估 formatVersion=2**，
而非已决定沿用 v1 或直接宣称兼容。plan 必须比较新版本与明确替代格式，冻结目录/database/API 各自版本和拒绝未来版本行为。
移动不换身份；复制不能产生同身份第二写者。网络盘/云同步与离线副本的全球唯一写者不是当前保证。

## 5. 四层隔离：保证与不保证

### A. 数据

各区数据库与对象归属独立。所有查询、修改、事件、产物访问均用当前认证身份及明确目标工作区授权；
资源引用不能靠客户端路由或请求体“我有权限”越界。A 的资源 ID 放到 B 请求中必须被拒绝。

### B. 生命周期与普通故障

关闭 A 不关闭 B、不取消 B 任务。候选格式错误、资源错误、缺依赖限于其归属范围。
A 数据库损坏应拒绝 A 打开/写入，但 B 中不依赖 A 的已授权操作继续可用。
安装身份、全局授权、共享持久化结果未知时，可阻断确实依赖这些事实的相关全局操作，须说明原因和影响范围。
不为“局部可用”绕过共享安全不变量。

### C. 执行与资源

高风险插件/任务按需受控执行进程，规定超时、输出上限、取消、排空与资源限制。
A 执行进程崩溃不应自动终止 B 的任务。安装总容量不能拆成每目录一份，必须公平调度或每区限制防长期独占。
子进程、目录 Trust 或 cwd 均非 OS 安全沙箱，恶意原生代码防护须另设计验证。
M1 无任务/插件执行；本层的运行验收归 M4/M5，不虚称首片已证明。

### D. 共享影响

第一版共享 Host 进程。Host 崩溃、内存耗尽、磁盘满、机器断电可能影响多个区；不承诺完全故障独立。
逐区运行子进程是有需求后另立功能的增强，不顺手实施；需单独定义数据库持有者、锁、授权、恢复。

### 状态不可混用

| 维度 | 必须表达的含义 |
| --- | --- |
| 工作区业务状态 | 活跃/归档/业务未就绪等业务条件；关闭不等于归档 |
| 目录生命周期 | 未打开/打开中/已打开/排空关闭中/已关闭/打开拒绝；损坏是拒绝原因，不是业务归档 |
| 访问模式 | 无访问/只读/可写；打开不自动授予写权限 |
| Run 逻辑状态 | 用户看到的进行/取消/超时/终态 |
| 物理收尾 | IO/Worker/Provider 仍被持有或已收敛 |
| 持久化状态 | 未提交/已确认/已拒绝/结果未知；连接断开不能推导回滚 |

具体状态枚举、错误码与转换由后续 plan/contracts 固定；上述维度不能合成一个 status。

## 6. 跨工作区协作（后续独立功能）

默认不开放任意跨区互访。未来只提供有真实消费者的受控查询、明确业务能力调用、事件通知。
强制链路：来源身份 → 来源访问策略 → 目标公开能力/授权 → 目标业务提交者 → 受限结果/回执。
不得直连其他区数据库或任意目录，不继承目标全部权限；目标 owner 完成目标写入。
不传原始凭据、活句柄或旧审批，不承诺双库天然原子；必须定义部分成功、取消、超时、重复/去重与审计。
这些原则现在约束架构，具体协议不混入 M1，不预建空消息总线。

## 7. Studio 与 Build（后续功能）

Studio 是建设客户端，链路是需求 → Host 生成服务 → 声明式页面/资源候选 → 结构/依赖检查 →
差异预览 → 用户确认 → Host 正式提交 → 客户端渲染。
布局/组件/数据绑定/动作属于声明式页面契约；任意 React/Vue 源码不得进入可信依赖图。
没有真实接口、业务能力或 renderer 时明确 unavailable；不使用假数据和空操作宣称可用。
Build/Studio 保存成果绑定工作区正式版本，不能只留在对话；前端分别实现 renderer，不每次重编译 Host。

## 8. 首期支持与明确排除

支持目标：经测试的 Windows 本地文件系统、单安装 Host、全新目录和合成数据、独立后端、后续 React。
具体本地文件系统与支持矩阵在 M1 plan 验证后固定，不把“Windows”理解为任意磁盘形态。

排除默认支持：网络盘、云同步、多 Host 协同写、旧库/凭据自动导入、未知副作用自动续跑、跨机继承权限、未验证跨平台锁。
当前功能执行权限与禁止事项只在[授权记录](<../specs/001-host-workspace-foundation/authorization.md>)维护；本文件的产品非目标不随执行阶段推进而扩大。

### 8.1 平台支持矩阵与声明门（proposed；尚未交付跨平台支持）

| 平台 | 路线归属/状态 | 允许的支持声明 |
| --- | --- | --- |
| Windows 11 x64、本地直连 NTFS、普通非重解析目录 | 001/M1 固定 profile；已有局部前置证据，完整业务验收仍以001任务与证据为准 | 只声明已验证的具体范围，不外推任意 Windows/磁盘/架构 |
| Linux | M8 proposed；尚未实现/验证 | 原生验收通过前不得称 supported；发行版、架构、内核/文件系统、桌面或 headless 秘密存储前提在对应 spec/plan 冻结 |
| macOS | M8 proposed；尚未实现/验证 | 原生验收通过前不得称 supported；系统版本、架构、文件系统、签名/发布及秘密存储前提在对应 spec/plan 冻结 |

Host 跨平台、工作区跨 OS 搬迁、桌面壳跨平台打包是三个独立验收面。M8 不自动交付跨 OS 目录可移植性；与 M7 的格式/迁移/排空协议共同验收前，不承诺直接拷目录跨 OS 即可写入，更不迁移活授权或秘密。其他平台、架构及文件系统不从 Go 工具链支持列表自动继承支持。

## 9. 唯一阶段路线与退出证据

| 阶段 | 交付归属 | 退出证据（不是当前通过声明） |
| --- | --- | --- |
| M0 | 宪章、能力/行为观察基线、协议范围、首片规格 | 工具真实初始化、引用/一致性自查、用户规格评审 |
| M1 | 独立服务、可信连接、目录身份/登记/打开关闭、单写者、最小正式资源保存/重开 | [001 规格](<../specs/001-host-workspace-foundation/spec.md>) 的真实多进程与落盘闭环全部通过 |
| M2 | 完整资源版本、不可变对象及提交协议 | 摘要字节夹具、并发提交、对象先于引用、保存未知/投影失败边界；不得削掉 M1 最小保存/重开 |
| M3 | 外部候选、差异、Apply、Build/Studio | 陈旧候选拒绝、显式确认、真实接口/renderer、成果重开；Build 安装总量32/64/64的跨区累计/满额负例，不按目录乘额 |
| M4 | 插件准入、精确依赖、激活、执行隔离 | generation/权限/依赖负例、执行进程故障/输出/排空验证 |
| M5 | Provider、凭据、Run、预算、事件、审批、恢复 | 保存前无派发、安装总容量、取消/物理收尾/迟到交付、未知副作用不自动续跑 |
| M6 | 现有 React、第二客户端、服务发现、多客户端 | 两种真实消费者走同一公共协议，不依赖私有客户端写者 |
| M7 | 快照、停机移动、克隆、可移植性、旧 Host 退役 | 排空/未知结果门禁、身份/授权不复制、逐能力替代证据及另行迁移授权；跨 OS 搬迁另须对应 M8 平台验收 |
| M8（proposed） | Linux/macOS 原生 Host、平台适配器与构建/发布支持矩阵；保持同一业务核心与公共协议权威 | 各平台分别完成下列原生安全/持久性与业务闭环，明确支持/拒绝矩阵及发布证据；不以交叉编译或 Windows 结果代替 |
| 后续专项 | 跨区协作；有需求支撑的更强进程隔离 | 分别立 Spec Kit 功能，不抢占本轮范围 |

M8 是新增的平台专项编号，不重编号 M0–M7，也不扩大001。**以 M1 的稳定业务闭环/端口为基线即可另立 Spec Kit 功能评审，不要求等待 M2–M7 全部完成**；这不是当前并行实施授权。Linux/macOS 可拆为各自有原生证据的切片，具体先后在该功能确认；共享核心/契约修改须单 owner 集成，不能与001另一会话并发覆盖。M7 在已支持平台内的备份/移动不依赖新增平台完成。

M8 每个拟支持 OS/架构/文件系统 profile 的退出门至少包括：

1. **构建与分发**：显式目标/profile、依赖与补丁分流、原生可执行产物及对应运行/安装验证；CLI/后端发布与桌面壳分别声明。交叉编译仅是早期检查。
2. **本机信任与秘密**：原生用户/对端身份、客户端与服务端双向核验、私有目录与秘密保护、过期/撤销，以及错误用户/伪装服务/弱权限的负例；不能以匿名 loopback、明文文件或公共 HTTP 登录替代当前引导。
3. **目录与单写者**：真实第二进程竞争、异常退出/释放、路径替换/符号链接/物理身份与权限负例；锁机制不同但不弱化单 owner、固定对象与实际排空要求。
4. **存储与失败**：逐平台真实 SQLite/VFS 同步及刷写失败、提交 unknown、排空失败、完整 Host 停止后重启重开；保留安装/工作区库分责，不把进程 kill 验证冒充硬件断电保证。
5. **一致业务与契约**：同一权威契约/字节夹具、当前身份/目标工作区校验、串区/越权拒绝、真实保存与重开、多工作区互不误关闭；记录平台 profile 差异而不 fork 业务协议/数据库事实 owner。
6. **兼容边界**：明确不支持场景及错误，验证 Windows 固定 profile 的相关回归；跨 OS 搬迁与 M7 联合证明身份、schema/路径兼容、授权不继承与未知结果处理，不直接复用旧安装库或凭据。

**M1 通过不等于完整 Host 重写或旧 Host 已替换。** M1 即使分成实现子片，最终真实保存/完整重启重开仍由 001 负责，不延期给“以后”。
迁移矩阵中的每项未迁移能力必须保留明确状态；未核对不等于可以删除。
