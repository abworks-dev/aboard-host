# 变更记录

本文件记录包能力和已知边界；包版本不等于 GitHub Release 已发布。实测修订、命令与结果以[验证记录](<docs/verification.md>)为准。

## Unreleased — 意图反馈与项目流程兼容

- 保持五个命令、现有目录、Spec Kit `==1.2.1` 兼容基线及包版本 `0.1.0`；本节为尚未发布的开发变更，不是新 Release。
- 从已有产品 / brief / 架构 / 决策记录识别任务相关意图，区分接受的目标与从代码反推的假设；不强制新建 Motivation 文件或固定行数。
- 为端到端入口增加受授权的局部回退：实现证据可推动最小技术计划 / 任务修订，但不能自行改目标、业务行为、验收、重要约束或权限；单阶段入口仍只改本阶段允许的产物。
- 保持稳定 ID、有效工作和重要取舍理由，明确最小同步链，不增加平行任务 / 决策体系或全项目重生成。
- 明确证据覆盖上下文、历史结果保留、受影响当前结论 `unverified`、验证义务重新打开与局部重验；不把历史通过带到改变后的对象，也不全量取消无关有效结果。
- 同步执行契约与采纳说明，并补充静态 prompt 回归和**未执行的真实 Agent 行为场景**。确定性验证结果另见[验证记录](<docs/verification.md>)；不据此宣称真实模型遵循新机制。

- 条件化接入项目已有的 clarify / 明确规格批准 / checklist / analyze 门禁：端到端请求不推定批准，保留 core 辅助技能；Agent 修复其负责的文档缺陷，不自勾人工批准或未运行的验证。
- plan 逐项记录适用宪章原则的设计与验证证据；core converge 追加项保留原 ID，仅在获准的 tasks 阶段补齐 AB 追踪映射，implement-only 不自改上游定义。
- 只读任务约束覆盖间接 helper 副作用；PowerShell 专项真实验证前置产物检查及进程级 no-persist locator 保全。增加 Windows CI 检查、新采纳文档、六条待执行行为场景和独立的合成模型夹具准备工具。
- 新增检查的实际结果与模型探针边界见验证记录；`prepare_host_eval.py` 只准备夹具，不会调用模型或把场景标成通过。

## 0.1.0 — 首版实现，发布状态未确认

### 新增

- 提供单一 preset `ab-engineering-baseline`：用自然语言入口 `speckit.ab.run` 按任务风险推进必要的规格、计划、任务、实现和验证，不强迫小修生成三份文档。
- 以 `replace` 覆盖 `speckit.specify`、`speckit.plan`、`speckit.tasks`、`speckit.implement`；直接调用单阶段只完成该阶段。
- 提供现有项目规则采纳、feature 定位、稳定追踪标识、依赖 / 所有权、实现与诊断修复循环、真实证据状态等提示词约定，不另建项目治理权威。
- 提供可维护提示词源与自包含生成命令，以及构建、一致性检查、静态验证、确定性隔离安装测试和 allowlist 打包工具。
- 打包输出干净的本地安装 payload、版本化 ZIP 和 SHA-256 文件，避免官方 `--dev` 复制整个源码仓库；不自动创建远端 Release。
- 提供中文安装、现有项目采纳、执行契约与发布文档；项目采用 MIT 许可，保留 Spec Kit / Lean 的完整上游归因与许可声明。

### 兼容与边界

- 首版仅声明兼容官方 Spec Kit `==1.2.1`，开发依赖固定上游提交 `9dca9bf42a031765ee5e5f2371137f2f26967e11`。
- 文档面向 `dsh`、`claude`、`codex` skills 布局；实际宿主发现能力仍须现场确认。`generic` 不支持本包命令覆盖。
- 不要求安装 Lean；不增加 extension 依赖、Hook、MCP、原生权限控制；不覆盖既有宪法或项目贡献者规则。
- 权限隔离、硬预算和跨会话自动续跑由宿主负责；提示词不是守护进程或强制安全边界。
- 更新遵循官方先移除再安装的非事务流程；停用不清除已生成命令，移除不回滚业务变更。

### 验证状态

- 本条目描述首版已实现内容，不预先宣称构建、安装或发布已通过；确定性实测由[验证记录](<docs/verification.md>)填入。
- 尚未完成独立的真实宿主 / LLM 行为验收。行为用例定义、静态校验和 CLI 安装成功均不能替代模型行为或真实业务验收。
